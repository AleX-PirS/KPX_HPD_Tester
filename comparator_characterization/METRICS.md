# Метрики характеризации компараторов

Справочник соответствует версии 0.22.0. Формулы относятся к сохраненным CSV. Имена столбцов остаются английскими при любом языке графиков.

## Координаты, группировка и единицы

Один пиксель всегда задается физическими `column,row`: столбцы 16..31, строки 0..31. AB характеризует CMP_B, BC характеризует CMP_C, CD характеризует CMP_D. Верхний компаратор окна задается нелимитирующим.

Повторы группируются по пикселю, этапу, trim, GAIN, порогу, амплитуде, FCLK и фазе инжекции. Матричные квантили относятся к распределению пикселей при одном условии. Сводки разных амплитуд, кодов усиления, частот и режимов инжекции сохраняются раздельно.

Суффиксы `_v`, `_mv`/`_millivolts`, `_codes`, `_hz`, `_s`, `_c`, `_electrons` означают В, мВ, коды ЦАП, Гц, секунды, кулоны и электроны. `_fraction` означает долю 0..1. `NaN` и пустые числовые ячейки означают отсутствие оценки, а не нулевой шум или подтвержденную неисправность.

## q90, q95 и другие статистики

Для отсортированных конечных значений x[0] <= ... <= x[n-1] квантиль q(p) вычисляется линейной интерполяцией: h=(n-1)p, i=floor(h), a=h-i; q(p)=(1-a)x[i]+a*x[min(i+1,n-1)].

| Обозначение | Формула и смысл |
|---|---|
| `mean` | sum(x)/n, среднее. |
| `median`, q50 | q(0.5), медиана. |
| q10, q90 | q(0.10), q(0.90). Полоса q10..q90 содержит центральные 80% распределения. |
| q95, p95 | q(0.95), 95-й процентиль. Это не доверительный интервал и не вероятность правильности fit. |
| q05..q95 | Центральный 90%-ный интервал распределения. |
| `std` | Для статистики повторов и сводок пикселей выборочное СКО: sqrt(sum((x-mean)^2)/(n-1)). При n<2 отсутствует. |
| `SEM`, `sem` | std/sqrt(n), оценка неопределенности среднего по независимым повторам. При одном повторе отсутствует. |
| `MAD`, `mad` | median(abs(x-median(x))), без коэффициента 1.4826. |
| `robust_sigma` | 1.4826*MAD, если данный метод явно использует нормальную эквивалентную ширину. |
| `RMS`, `rms` | sqrt(mean(x^2)). Для отклонения от цели включает смещение и разброс. |
| `peak_to_peak` | max(x)-min(x). |
| `abs_q90`, `abs_q95` | Квантиль абсолютного значения, например q95(abs(V0-Vtarget)). |
| `minimum`, `maximum`, `min`, `max` | Крайние конечные значения группы. |

Пример: `residual_abs_q95_v=0.002` означает 95-й процентиль абсолютного отклонения порога, равный 2 мВ. `background_count_q95=1200` означает процентиль фонового счета выбранной группы, а не 95% от N. Крайние квантили при малом числе наблюдений неустойчивы; число пригодных точек нужно смотреть вместе с квантилем.

## Шум: noise_statistics.csv и noise_fit_results.csv

`repeat_count_total/valid/invalid` содержат число всех, пригодных и непригодных повторов. `repeat_count_saturated` и `repeat_fraction_saturated` описывают насыщение. `mean_count`, `median_count`, `std_count`, `sem_count`, `min_count`, `max_count`, `mad_count` считаются по пригодным повторам при одном пороге. `points` и `nonzero_points` описывают число точек кривой и число ненулевых точек.

| Поле | Расчет и интерпретация |
|---|---|
| `center_fit_v`, `sigma_fit_v` | Центр V0 и ширина выбранной модели шумовой кривой. |
| `fit_model` | Способ аппроксимации, например `gaussian_log_quadratic`, `edge_probit`, `plateau_center_fallback`. |
| `fit_amplitude_count`, `fit_background_count` | Амплитуда A и постоянный фон C0 модели. |
| `center_centroid_v` | integral(V*w(V)dV)/integral(w(V)dV), w=max(C-q10(C),0). Интегралы считаются трапециями с учетом неравномерного шага LUT. |
| `center_max_v`, `center_max_dac_code` | Центр связного максимального плато с учетом SEM и весов счета после удаления постоянного фона. |
| `center_selected_v`, `center_selected_method` | Итоговая оценка центра и выбранный метод. |
| `candidate_center_fit_v`, `candidate_sigma_fit_v` | Пробная модель, сохраняемая и при ее последующей отбраковке. |
| `centroid_applicable`, `maximum_estimator_applicable` | Применимость соответствующих оценивателей. |
| `curve_shape`, `diagnostic_flags` | Форма кривой и ограничения: обрезанный пик, асимметрия, насыщение и другие признаки. |
| `scan_min_voltage_v`, `scan_max_voltage_v` | Реально измеренный диапазон данной кривой. |

Для колокола C(V)=C0+A*exp(-(V-V0)^2/(2*sigma^2)); C0 оценивается через q10(C). Положительная часть выше 3% динамического диапазона аппроксимируется квадратичной функцией логарифма счета с весами, связанными с SEM. Для одностороннего отклика используется probit-модель края. Ширина этого колокола и sigma сигнальной S-кривой являются разными величинами.

## Качество и неопределенность fit

| Поля | Формула/смысл |
|---|---|
| `fit_r2`, `plane_fit_r2`, `transfer_r2` | R²=1-sum((y-yfit)^2)/sum((y-mean(y))^2). Может быть отрицательным; для постоянного y оценка может отсутствовать. |
| `fit_rmse_efficiency`, другие RMSE | sqrt(mean((y-yfit)^2)) в единицах соответствующей величины. |
| `fit_reduced_chi2` | sum(((y-yfit)/SEM)^2)/dof для точек с пригодным SEM; dof учитывает число параметров. |
| `*_uncertainty_*` | Стандартная неопределенность параметра из диагонали ковариационной матрицы модели. |
| `fit_points`, `fit_points_available_on_physical_branch` | Использованные точки и доступные пригодные точки физической ветви. |
| `fit_points_in_transition_core` | Точки локального ядра перехода. |
| `fit_status` | Статус применимости и качества результата, не диагноз пикселя. |

Статистическая неопределенность fit не включает автоматически все ошибки LUT, емкости инжекции, экспозиции, температуры и дрейфа.

## Подстройка и эквализация

Предварительно измеряются центры при trim 0, 16 и 31. Код 16 является номинальной точкой нулевого смещения trim-ЦАП, но не предпочтительным рабочим кодом. Если отклонение среднего якоря не разрешается относительно неопределенности fit и половины локального шага trim, применяется линейная модель по всем пригодным якорям. При разрешимом изгибе применяется кусочно-линейная модель 0..16..31. Если из-за разворота существуют два решения, выбирается код с меньшим прогнозируемым остатком эффективного порога; запас до края используется только при равном остатке. После этого локальные коды обязательно измеряются, и итоговая карта предпочитает фактический минимальный остаток прогнозу.

`trim_low_side_slope_v_per_code=(V16-V0)/16`, `trim_high_side_slope_v_per_code=(V31-V16)/15`. `trim_reference_linearity_error_v=V16-[V0+16(V31-V0)/31]` показывает отклонение центральной точки от одной endpoint-прямой. `trim_curvature_resolution_limit_v` содержит использованный порог разрешения изгиба, `trim_curvature_significance_sigma` его статистическую значимость, `trim_curvature_resolved` итог решения, а `trim_model_selected` выбранную модель. `trim_corner_direction_reversal=True`, если два наклона имеют разные знаки или один равен нулю. Это диагностический признак нелинейного угла, а не автоматическая неисправность; такой пиксель получает расширенный измеренный поиск.

`target_voltage_v` является целью эквализации, а `selected_measured_residual_v` равен V0 выбранной измеренной настройки минус цель. `center_selected_method` указывает, взят ли центр из fit, центроида или максимума. Рекомендуемый код без проверочного измерения не равен измеренному результату эквализации.

Сводка после эквализации содержит `pixel_count`, `valid_center_count`, `failed_fit_count`, число выбранных fit/centroid, статистики `center_*`, `residual_*` и число/долю крайних trim-кодов. Для остатка r=V0-Vtarget: `residual_mean_v`=mean(r), `residual_rms_v`=sqrt(mean(r²)), `residual_abs_q95_v`=q95(abs(r)). Крайний trim-код сам по себе не доказывает неисправность.

Таблицы `uniform_trim_characterization` и `uniform_trim_summary` описывают зависимость центра от общего trim-кода: среднее, медиану, СКО, MAD, q10/q90, долю успешных fit и распределение ширины шума.

## S-кривые: счет, фон и нормировка

Пусть S означает сигнальный счет, B означает фактически измеренный background, N означает число импульсов для анализа.

| Поле | Расчет |
|---|---|
| `signal_count`, `background_count` | Сохраненные S и B. Отсутствующий sparse-background остается NaN. |
| `background_evaluation_count` | B текущей пары либо max(B_left,B_right) по пригодным контрольным точкам текущего запуска, окружающим этот DAC. Экстраполяции нет. |
| `background_evaluation_valid`, `background_evidence_source` | Пригодность и происхождение контрольной оценки. Она не становится raw-измерением. |
| `background_limit_count` | N*max_background_fraction, обычно 0.01N. |
| `background_low` | Контрольная оценка ниже лимита. В paired дополнительно учитывается доступный noise reference; в sparse старые counts не определяют пригодность. |
| `background_corrected_detected` | S-B в paired; S в sparse. Название столбца сохранено для совместимости. |
| `signal_processing_method` | Явно сообщает, выполнено ли вычитание парного фона или анализ сигнала с контрольными точками. |
| `efficiency` | (S-B)/N в paired; S/N в sparse. |
| `efficiency_binomial_sem` | sqrt(e*(1-e)/N), где e ограничена диапазоном 0..1 только при расчете этой оценки SEM. |
| `expected_background_rate_hz_from_noise_scan` | mean_count старого noise scan / его экспозиция. Диагностическое поле, не вычитается в sparse. |
| `expected_background_count_from_noise_scan` | Предыдущая частота счета, пересчитанная на текущую экспозицию при наличии длительностей. |
| `timing_nominal_injections` | Для PWM round(Freal*T); аппаратный счетчик фронтов отсутствует. |
| `stage_plateau_estimate_injections` | q75 сигнального плато этапа по пригодным чистым точкам. |
| `effective_injections_for_analysis` | Для PWM общая робастная оценка из медианы пригодных оценок плато этапов, округленная до целого. Иначе сохраненная нормировка. |
| `stored_injections_for_analysis` | Исходная нормировка до офлайн-уточнения. |
| `effective_to_timing_nominal_ratio` | N_effective/N_nominal. |
| `injection_denominator_method` | Способ получения N. |

Контрольные точки sparse никогда не смешиваются между пикселями, trim, этапами, амплитудами, tile-фазами и FCLK. Если пригодных контрольных данных нет, точка исключается из fit. В crosstalk фон фактически снимается для каждого повтора, чтобы сохранить signed-разность неинжектируемых пикселей.

## Физическая ветвь, V50 и sigma

`baseline_noise_boundary_code` является верхним DAC-кодом, где заданная доля активных пикселей имеет измеренный B>N*multiplier. `physical_branch_valid` оставляет коды не ниже этой границы. Если граница не найдена, надежный fit физической ветви не производится. Все точки шумового колокола остаются в raw и доступны на графиках счета.

`fit_valid_before_physical_branch` проверяет счетчики, насыщение, фон, активную инжекцию, положительное N и эффективность в пределах 0..1. `fit_valid` дополнительно требует физическую ветвь. `preferred_for_default_analysis` исключает дубли грубой фазы при наличии более точной; raw-дубли не удаляются. `quality_flags` перечисляет причины исключения.

| Поле | Расчет и смысл |
|---|---|
| `v50_v` | Порог 50% локального нормированного перехода по probit-fit. |
| `d50_code` | Аналогичная оценка в кодах, отдельная регрессия по измеренным DAC-кодам. Может быть дробной. |
| `d50_nearest_programmable_code` | Ближайший программируемый код по LUT для V50. |
| `sigma_v`, `sigma_millivolts` | Ширина перехода в В и мВ; коэффициент probit-регрессии по модулю. |
| `sigma_dac_codes` | Ширина в кодах по отдельной регрессии. |
| `threshold_domain_noise_sigma_*` | То же значение sigma, с явным указанием пороговой области. Это не ENC в электронах. |
| `fit_lower_plateau_efficiency`, `fit_upper_plateau_efficiency` | Оценки нижнего и верхнего плато после взвешенной изотонической обработки. |
| `fit_plateau_dynamic_range` | Верхнее плато минус нижнее. |
| `fit_isotonic_adjustment_rmse` | Взвешенное RMS изменения эффективности при монотонизации. |
| `fit_code_min`, `fit_code_max` | Измеренный диапазон локального fit. |
| `transition_direction`, `code_transition_direction` | Направление перехода по физическому напряжению и по коду. |

Модель имеет вид e(V)=L+(U-L)*Phi(±(V-V50)/sigma). После оценки плато используется преимущественно ядро 5-95% и ближайшие граничные точки. Веса probit-регрессии зависят от N*p*(1-p). Нелинейность LUT учитывается фактическими напряжениями.

`transition_not_resolved` означает, что в чистой области не достигнуто 90% нормировки. Для слабого сливающегося с шумом сигнала V50 и sigma остаются NaN. `transition_not_bracketed`, `transition_core_insufficient`, `insufficient_data`, `insufficient_plateau_dynamic_range`, `singular_fit` обозначают соответствующие недостатки данных или модели. `ok` требует пригодной модели и R²>=0.8; `poor_quality` сохраняет оценку по модели с худшим R², отдельно от успешной.

## Точность сетки и оперативные решения

`scurve_transition_precision.csv` содержит ближайшие измеренные коды ниже/выше D50 (`fine_lower_code_at_d50`, `fine_upper_code_at_d50`), их расстояние `fine_bracket_gap_code`, признак расстояния <=1 `fine_step_one_at_d50` и число точек 10-90%. Для адаптивной фазы плотными считаются коды с измеренным соседом на расстоянии 1.

`scurve_branch_summary.csv` содержит пределы и число измеренных кодов, диапазон физической ветви, число исключенных строк, нормировку и долю пикселей с шагом 1 у D50. `fine_grid_complete_step_one_between_min_max` может быть False при намеренно крупном шаге на плато; это не означает пропуск V50. `fine_unit_step_pair_fraction` описывает долю единичных соседних интервалов плотной сетки.

`online/scurve_sampling_*.csv`: `repeats` означает фактически выбранное число повторов; `background_checkpoint` означает наличие контрольного B; `transition_10_90`, `noise_reference_band`, `noise_started`, `weak_signal_dense` показывают основания плотного прохода. `effective_plateau_count_online` является оперативной оценкой N. `backfill_coarse_gap` фиксирует возврат для заполнения пропущенных кодов. `noise_tail_streak` считает подтвержденные соседние коды спада шума. Эти решения не заменяют офлайн-оценки и исходные снимки.

## Наводки и неинжектируемые пиксели

`inactive_signed_delta_count`=S-B при TST_EN=0 и tile_crosstalk. Отрицательные изменения сохраняются. `inactive_excess_hit_fraction`=max(S-B,0)/N сохраняет прежнюю метрику положительного избытка.

`inactive_noise_statistics.csv` группируется по этапу, FCLK, фазе, пикселю и DAC. `signal_mean_count`, `background_mean_count` являются средними S и B. `delta_mean_count`, `delta_std_count`, `delta_sem_count`, `delta_q90_count`, `delta_q95_count` описывают распределение попарных разностей по повторам. `delta_rate_hz`=mean((S-B)/T). `repeat_count` показывает число пригодных пар; SEM при одной паре отсутствует.

Crosstalk-сводки дополнительно сравнивают V50 и sigma разных плотностей инжекции для одних пикселей и амплитуд. `delta_v50_*` являются разностями относительно опорного разреженного режима, `sigma_ratio` отношением ширин, поля median/p95/max описывают распределение соответствующих величин. В tile_measurement неактивные MASK=0, поэтому их нули не являются измерением изменения шума.

## Зависимость от FCLK

`measurement_clock_noise_pixel_metrics.csv` сравнивает sigma и V50 того же пикселя при разных измерительных FCLK. Опорная частота записывается в таблице. Разности V50 имеют единицы В/мВ/коды; отношение sigma к опорной sigma безразмерно.

Сводка `measurement_clock_noise_summary.csv` содержит число пикселей, успешных и пригодных fit, их доли, среднее/медиану/MAD/q10/q90 ширины и медиану D50. `successful_fit_count` учитывает `ok`; `usable_fit_count` может включать `poor_quality`. Это сравнительный показатель ширины перехода, не спектральная плотность шума.

При загрузке trim reference применяется только карта подстройки. Новый noise scan проводится после ее применения; затем снимаются S-кривые при разных FCLK. Числовые шумовые данные прежнего эксперимента не используются.

## REF, заряд, усиление и линейность

В LUT-режиме ступенька dV=V_REF1-V_REF2 берется из измеренных LUT с условием dV>0. `requested_voltage_step_v` задается пользователем; `actual_voltage_step_v` является выбранной ступенькой LUT. Знаковая ошибка равна actual-requested; `absolute_voltage_step_error_v` является ее модулем. Общий REF1 фиксирован, коды REF2 различны, допуск по умолчанию 0.001 В.

В ручном режиме сохраняется одна точная пара кодов и `voltage_step_v`, введенный пользователем как эквивалент. `injection_charge_status=nominal_c_times_user_equivalent_delta_v`; индивидуальные `ref1_voltage_v`, `ref2_voltage_v` и физический порядок отсутствуют, поскольку LUT не использовалась. Номинальный заряд все равно равен `C_inj*voltage_step_v`. Одна такая точка не определяет независимый наклон V50(Q), поэтому обычный `scurve_pixel_gain_results.csv` требует минимум три амплитуды. При этом усиление A/Q в новых метриках GAIN-свипа вычисляется и для одной точки, если известна база и заряд.

Таблицы `*ref_step_availability*.csv` содержат `realizable` и причину пропуска. Алгоритм выбирает максимальное по числу ступенек совместное назначение, затем минимальный измеренный REF1. Индивидуально возможная ступенька может быть пропущена из-за общего REF1 или требования различных REF2. Если список пуст, соответствующий этап пропускается.

Q=Cinj*dV, `injection_charge_electrons`=Q/e, e=1.602176634e-19 Кл. `injection_charge_uncertainty_c`=abs(Q)*относительная неопределенность Cinj в текущей модели. Это номинальный заряд; неизвестные ошибки dV или Cinj нельзя считать автоматически учтенными.

`scurve_pixel_gain_results.csv` аппроксимирует V50=a*dV+b методом наименьших квадратов по минимум трем различным амплитудам. `v50_slope_v_per_injection_step_v`=a, `v50_intercept_v`=b. Дополнительная регрессия V50 по числу электронов дает `gain_mv_per_ke`=наклон*10^6.

`maximum_tested_linear_charge_electrons` для обычного амплитудного анализа выбирается по наибольшему измеренному префиксу из >=3 точек, где R²>=0.98 и максимальный модуль остатка не превышает max(0.002 В, 3% размаха V50). Сохраняются соответствующая ступенька и число линейных точек. Это диагностика V50(Q), а не прямое измерение насыщения выхода ЗЧУ.

В финальном ALL REF sweep пороги трех окон фиксированы. Для каждого окна определяется Q50 по пересечению 50% отклика, затем строится трехточечная зависимость порога от Q50. `joint_gain_mv_per_ke`, `joint_baseline_intercept_v`, `joint_transfer_r2` характеризуют эту регрессию. Здесь одноименное `maximum_tested_linear_charge_electrons` возвращает максимальный измеренный заряд только при R²>=0.98 трехточечной модели. Метод отличается от префиксной проверки обычного амплитудного анализа и не доказывает линейность всех промежуточных зарядов.

В осциллографической проверке REF `measured_step_clk_off_v/on_v` относятся к измерению с выключенным/включенным CLK; их разность показывает влияние тактирования. `capture_pass`, `pair_pass` сообщают выполнение настроенных критериев регистрации и допуска ступеньки.

## Покодовые метрики GAIN-свипа

`gain_sweep_pixel_metrics.csv` содержит одну строку на пиксель/GAIN/ступеньку.
Окно, FCLK и режим инжекции не смешиваются. `gain_sweep_summary.csv` хранит
число измеренных и пригодных пикселей, среднее/медиану/СКО/q10/q90 базы,
амплитуды и усиления в каждом таком условии. СКО выборочное, ddof=1.

| Поле | Определение |
| --- | --- |
| `baseline_v` | Эффективная база для выделения амплитуды из V50. |
| `baseline_source` | `scurve_zero_charge_intercept`: свободный член пригодной регрессии текущего GAIN; `gain_matched_noise_center`: noise-центр при том же GAIN; `shared_noise_center_assumed_gain_invariant`: общая noise-база с явным предположением; `unavailable`: базы нет. |
| `baseline_gain_invariance_assumed` | True только при переносе общей noise-базы между GAIN. |
| `effective_amplitude_v`, `amplitude_mv` | A=V50-baseline, в В и мВ. Отрицательные значения не заменяются модулем. |
| `gain_v_per_injection_step_v` | A/dV, безразмерный отклик относительно ступени REF. Alias: `secant_gain_v_per_injection_step_v`. |
| `nominal_gain_mv_per_ke` | A[В]*10^6/Q[электроны], вычисляется при одной ступеньке. Alias: `secant_nominal_gain_mv_per_ke`. |
| `gain_method` | `amplitude_over_charge`. Это вычисленный A/Q, а не независимый многоточечный наклон. |
| `amplitude_valid` | Fit S-кривой принят, база/амплитуда/ступенька конечны, A>0, dV>0. По умолчанию принимаются только fit_status=ok. |
| `charge_gain_available` | Дополнительно известен конечный положительный Q. Если Q неизвестен, A/dV сохраняется, A/Q остается NaN. |
| `metric_status` | Причина отсутствия пригодной амплитуды, например baseline_unavailable или scurve_fit_not_accepted. |
| `slope_gain_available` | Есть >=3 различные ступеньки, положительный конечный наклон, конечная база и R2>=настроенного порога, по умолчанию 0.98. |
| `slope_gain_v_per_injection_step_v` | Независимый наклон регрессии V50(dV). |
| `slope_nominal_gain_mv_per_ke` | Независимый наклон V50(Q) в мВ/кэ, если зарядная ось известна. |

В приоритете база из многоточечной регрессии, затем noise-центр при том же GAIN,
затем разрешенная общая база. Среди noise-этапов порядок: equalized_final,
baseline_noise, trim_16, trim_00, trim_31. Другой известный trim или FCLK не
используется. `GAIN_EQUALIZATION_ALLOW_SHARED_NOISE_BASELINE=False` запрещает
общую базу. Перенос baseline не подтверждает ее реальную независимость от GAIN.

## Индивидуальный подбор GAIN-кодов

`gain_equalization_targets.csv`: для каждого TARGET_GAIN и ступеньки матричная
цель A_target=median(A) или mean(A) при равномерном измеренном целевом коде.
`target_nominal_gain_mv_per_ke` имеет ту же статистику для A/Q.
`target_population` показывает число пригодных пикселей. Для одной ступеньки
среди пикселей требуется согласованный номинальный Q. При наличии регрессии
`target_slope_v_per_injection_step_v` считается по одному значению на пиксель.

Для пикселя p и измеренного кода g критерий:

`J(p,g) = w_A * mean_j(((A(p,g,j)-A_target(j))/A_target(j))^2)`.

Если пригоден независимый многоточечный наклон, добавляется
`w_G * ((slope(p,g)-slope_target)/slope_target)^2`.
При постоянном Q отклонение A/Q эквивалентно отклонению A, поэтому оно не
добавляется второй раз. `objective=amplitude_secant_equivalent` сообщает этот
случай; `amplitude_and_slope` сообщает совместный критерий.

Кандидат обязан иметь пригодные результаты на всех целевых ступеньках, тот же
известный Q и, для совместного критерия, пригодный наклон. Нельзя выбрать
неизмеренный код, интерполировать его или предполагать монотонность. Минимум
J выбирается независимо по пикселям. При численных равенствах (rtol=1e-9,
atol=1e-15) выбирается ближайший к TARGET_GAIN код, затем меньший код.

`gain_equalization_maps.csv` и индивидуальные `gain_map.csv` содержат column,
row,gain, changed, objective_score, candidate_code_count и recommendation_status.
`measured_code_proposal` означает пригодный измеренный кандидат;
`unresolved_preserve_target` сохраняет целевой код при отсутствии кандидатов.
`verified_in_mixed_gain_matrix=False` означает, что смешанная карта не измерена.
Плохие пиксели исключены по исходной маске. Неопределенные пиксели не исчезают
из карт и отдельно учитываются в числе unresolved.

`gain_equalization_predictions.csv` содержит baseline, амплитуду и A/Q
исходного целевого кода (`before_*`) и выбранного кода (`predicted_*`). Прогноз
берется из измеренного равномерного свипа, а не из новых измерений смешанной
матрицы. База сохраняется и на картах, поскольку смена GAIN может ее изменить.

`gain_equalization_summary.csv` сравнивает одинаковую пару физических пикселей
до и в прогнозе: `paired_pixel_count`, выборочные СКО амплитуды и усиления,
`*_paired_rms_to_target_v`=sqrt(mean((A-A_target)^2)),
`*_paired_abs_residual_q95_v`=95-й процентиль abs(A-A_target).
Также сохраняются числа разрешенных, измененных и неопределенных пикселей.
Улучшение суммарного критерия не гарантирует улучшение каждой отдельной
ступеньки в совместном многоточечном подборе. Подтверждение результата требует
повторного S-curve измерения с индивидуальной картой.

## Реальная проверка mixed GAIN-карты

`gain_verification_pixel_metrics.csv`: поля амплитуды, базы, A/Q, slope и
пригодности имеют те же формулы, но вычислены по новому аппаратному тесту.
`target_gain_code` обозначает задачу, не равномерный физический код.
`applied_gain_code` задает фактический индивидуальный код; `configuration_mode`
равен measured_mixed_gain_map. `baseline_source=mixed_map_fresh_noise_center`
означает noise-центр текущей карты; mixed_map_zero_charge_intercept означает
пригодную многоточечную регрессию текущего пикселя/карты. Предположение о
GAIN-инвариантной старой базе здесь не применяется. `sigma_v` относится к
ширине нового S-перехода, не к наклону gain-кривой и не к спектральной плотности.

В `gain_verification_comparison.csv` поля before_* и predicted_* взяты из
исходного равномерного свипа, actual_* из нового теста. При ALL с опорной картой
прогноз пересчитывается из измерений именно выбранных кодов для каждого окна;
если код там не измерялся, прогноз остается NaN, но реальное измерение возможно.
`actual_amplitude_residual_v`=A_actual-A_target;
`prediction_error_v`=A_actual-A_predicted. Missing/invalid actual остается NaN
с actual_metric_status, не заменяется нулем.

`gain_verification_summary.csv` сохраняет все pixel counts и число invalid.
before/predicted/actual paired СКО, RMS до цели и q95 abs residual считаются
по одной и той же тройке физических пикселей с пригодными всеми тремя откликами.
`paired_prediction_error_rms_v`=sqrt(mean((A_actual-A_predicted)^2)).
Отсутствующий прогноз может исключить пиксель из paired-сводки, но не из общей
карты или real valid_pixel_count. СКО gain в мВ/кэ имеет ddof=1.

В `measured_gain_map.csv` column,row,gain совместимы с GAIN_MAP_CSV.
measured_in_mixed_gain_matrix=True означает факт завершенного аппаратного
прохода. valid_amplitude_step_count/required_step_count сообщают пригодность;
all_response_steps_valid требует пригодного A на каждой целевой ступеньке.
Никакой допуск к target и автоматический equalization pass/fail не добавлен.
Исходное verified_in_mixed_gain_matrix=False в предложении не перезаписывается.

## Согласованные AB/BC/CD после GAIN

`gain_verification_joint_window_metrics.csv` создается только для общего
ALL-режима: один физический GAIN и одинаковые source trim B/C/D между окнами.
Строки относятся к одному пикселю, TARGET_GAIN, FCLK, режиму и REF-step/Q.
Полная структура содержит и непригодные строки, complete_response=False.
Общие составляющие таких строк остаются NaN. Разные GAIN-коды между окнами
не дают совместного результата.

Для каждого окна w:

- `relative_gain_deviation_w`=A_actual,w/A_target,w-1. При одинаковом Q это
  также относительное отклонение A/Q. Нормирование по собственной цели окна
  не показывает общий абсолютный сдвиг всей матрицы данного окна; для этого
  сохранены actual_amplitude_w_v и actual_gain_w_mv_per_ke.
- `baseline_offset_w_v`=baseline_actual,w-median(baseline_actual,w по пригодным
  пикселям окна). Абсолютные базы также сохраняются отдельно.
- `sigma_w_v`: ширина соответствующей новой S-кривой.

`common_gain_deviation`=median трех relative_gain_deviation;
`differential_gain_range`=max-minus-min тех же трех величин.
`common_baseline_shift_v`=median трех baseline_offset;
`differential_baseline_range_v`=max-minus-min этих baseline_offset.
На графиках относительные gain величины умножаются на 100 для процентов,
baseline на 1000 для мВ.

Общая составляющая совместима с общей аналоговой/инжекционной причиной;
дифференциальная с comparator/window/calibration effects. Однозначное
разделение причины по этим метрикам не выполняется, categorical fault labels
и произвольные пороги диагноза не вводятся. При одной ступени A/Q определен,
но зависимость gain от Q и самостоятельный многоточечный slope неизвестны.

## Пространственные метрики и ALL

Пространственная плоскость baseline имеет вид V(c,r)=a+b*c+d*r. Коэффициенты b,d и разность значений плоскости на краях описывают градиент. `detrended residual` равен измеренному V минус плоскость; его RMS/СКО описывают локальную неоднородность. Совместимость с IR-drop не является доказательством причины.

Суффикс `spatially_compensated` относится к диагностическому удалению пространственной составляющей при каждой амплитуде/окне. Исходные результаты сохраняются; скорректированные не подменяют их.

В `multi_window_pixel_metrics.csv` суффиксы AB/BC/CD связывают метрики одного физического пикселя. `baseline_offset_*_v` является отклонением от медианы соответствующего окна. `common_baseline_shift_v` является медианой трех таких отклонений; `common_baseline_robust_z` является медианой нормированных робастных отклонений. Разности окон описывают дифференциальную составляющую.

Корреляция Пирсона равна cov(x,y)/(std(x)*std(y)); ранговая корреляция считается по рангам. Число общих пригодных пикселей сохраняется рядом. В PCA полные строки трех окон центрируются и стандартизуются, затем выполняется SVD. Доля объясненной дисперсии каждой компоненты равна s_i²/sum(s_j²); знак компоненты условен. Общая компонента может быть совместима с общей причиной в ЗЧУ или питании, но не устанавливает ее.

Классификационные поля, `reason_codes`, masking candidates и предложенные trim-коды являются диагностическими рекомендациями. Для подтверждения нужны повторные измерения; они не равны автоматически установленной неисправности.
