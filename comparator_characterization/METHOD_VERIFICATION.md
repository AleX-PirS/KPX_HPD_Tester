# Независимая проверка методики калибровки

Сценарий `method_verification` добавлен для экспериментальной проверки положений
статьи. Он не меняет протокол УПО, смысл MASK/TST_EN или принятую карту счетчиков.
Контроль аппаратуры и аварийное восстановление выполняет существующий
`characterize_comparator`. Инструменты открываются только после проверки конфига.

## Протокол

- Исходные точки калибровки trim остаются 0/16/31, с существующим локальным
  измерительным уточнением. Нового принудительного предпочтения коду 16 нет.
- Если METHOD_TRIM_REFERENCE пуст, отдельно обучаются выбранные AB/BC/CD.
  Если задан, загружаются только готовые trim-карты и их фиксированные цели.
  Для ALL источник должен содержать карты всех трех окон.
- Затем ВСЕ выбранные карты B/C/D объединяются в одну пиксельную конфигурацию.
  Заданный GAIN устанавливается также перед noise-сканом, а не только перед инжекцией.
  При изменении GAIN, FCLK или EO старая карта разрешена как исходный объект
  проверки, но ее пригодность в новых условиях заново проверяется.
- Калибровки пороговых ЦАП сверяются по SHA256. Сохраняются исходные ссылки,
  хеши карт/metadata, снимок конфига и `frozen_pixel_config.csv`.
- Проводятся R НОВЫХ noise+S-сканов для каждого окна, без новой подстройки.
  Данные обучения исключены из итоговых интервалов. Направление скана может
  чередоваться; дрейф/гистерезис надо проверить до принятия модели повторяемости.
- S-скан использует шаг 1 по всему заданному SCURVE.dac_range, все повторы,
  paired background, без остановки после шумового колокола. Это режим проверки,
  он заведомо медленнее быстрого рабочего sparse-скана. Нужен диапазон, который
  реально содержит оба края; отсутствующая ветвь не достраивается симметрией.
- AB/BC/CD измеряются последовательно при общей замороженной конфигурации.
  Верхняя граница в этих сканах выбирается по прежнему нелимитирующему правилу.
  Это еще не проверка реального узкого окна. Компаратор A не получает здесь
  независимую trim-калибровку: число проверяемых подстроенных границ для ALL K=3.

## Проверка рабочих окон

`metadata.METHOD_VERIFICATION.upper_threshold_codes` принимает явные коды:
например `{"BC": (код_верхнего_порога_1, код_верхнего_порога_2)}`. Пустой словарь
отключает дополнительный этап. Значения надо выбрать по своим измеренным LUT и
рабочей области. Уменьшение кода не всегда уменьшает физический порог.

Для каждого кода выполняется полный скан нижнего порога, все trim-карты остаются
зафиксированными. Результат: `window_grid_points.csv` и карты счета по физическим
нижнему и верхнему напряжениям. Скан не передается обычному fit одиночного края и
не участвует в сертификации noise-центра. Это дает данные о взаимном влиянии
границ; адекватность оконной логики надо подтвердить по реальному отклику.
Счетчик может регистрировать пересечения/импульсы, а не мгновенное пребывание
напряжения между порогами. Поэтому вероятность Phi(U)-Phi(L) автоматически
к измерению не приписывается. В текущем grid выполняется одна серия на верхний
код; доверительный интервал ширины окна автоматически не заявляется.

## Что считается

`bipolar_points.csv`: все измеренные коды, средний валидный signal count,
paired background, число попыток/валидных/допустимых повторов. Центральная шумовая
область остается на графике. Ошибка чтения и насыщение не превращаются в ноль.
Fit краев использует валидные пары с background <= max_background_fraction*N;
фон не вычитается как тождественный процессу при включенной инжекции.

`bipolar_results.csv`: независимо найденные V_- и V_+, их ширины переходов,
статусы fit, H=(V_+-V_-)/2, A_+=V_+-b_off, A_-=b_off-V_-,
eta_off=(V_++V_--2*b_off)/(V_+-V_-). b_off берется из нового noise-скана
того же пикселя, trim и условий. Это эффективный noise-центр, не отдельно
измеренное смещение компаратора и не активная база ЗЧУ.

Номинальное усиление при одной ступеньке вычисляется:
G[мВ/кэ]=10^6*H[В]/Q[электроны]. Q=Cinj*|DeltaV_REF|/e.
Число сохраняется, если оба края разрешены и Q положителен. Интерпретация H как
сигнальной амплитуды требует проверки счетного оператора и равенства модулей
зарядов двух событий/полярностей. В общем случае H их полусумма.
Отдельное однополярное усиление A/Q остается в существующем S-анализе.
Один Q дает A/Q; несколько Q позволяют дополнительно оценить наклон и нелинейность.

`method_window_diagnostics.csv`: H каждого окна и отклонение от медианы
разрешенных окон того же пикселя, Q, GAIN, FCLK, фазы и повтора. Согласованное
изменение всех окон совместимо с изменением общего тракта; изолированное
отклонение совместимо с различием компараторных каналов. Это диагностические
признаки, а не доказанный диагноз или автоматическая коррекция карт.

## Неопределенность и допуск

Для каждого исходного пикселя i и выбранного компаратора k берутся R валидных
центров независимых повторных сканов. Цель t_k фиксируется ДО серии проверки.
При явно принятой нормальной стационарной модели повторных оценок используется

    h_ik = t_(1-alpha/(2*M*K), R-1) * s_ik/sqrt(R) + E_cal
    I_ik = [mean(b_ik)-t_k-h_ik, mean(b_ik)-t_k+h_ik].

Это интервал для среднего центра в заданных условиях, не предиктивный интервал
будущего измерения. Поправка Бонферрони не требует независимости разных пикселей;
независимость и стационарность повторных оценок каждого пикселя все равно нужны.
E_cal является заданной консервативной границей (LUT, цель, дискретизация,
модельная ошибка), а не подменой ее ковариацией fit.

Статусы: `confirmed_within`, если весь интервал внутри +/-допуска;
`confirmed_outside`, если весь с одной стороны вне допуска; иначе
`not_confirmed`. Отдельно: `limits_not_configured`, `incomplete_repeats`,
`repeat_model_not_validated`. Для совместной годности пикселя должны быть
подтверждены ВСЕ выбранные границы. Маскированные/непрочитанные пиксели не
исключаются из исходного знаменателя M и не становятся подтвержденно годными.
Число проходов R=3 само по себе не доказывает нормальность или стационарность.
Ковариация fit S-кривой остается описательной и не используется как готовый
интервал с гарантированным покрытием.

По умолчанию допуск/E_cal не заданы, флаги подтверждения физической и
статистической моделей False. Данные и графики строятся, но сертификат годности
не выдается. Допуски задает требование к микросхеме, E_cal надо обосновать.

## Выходные файлы и повторный анализ

`RESULTS_DIR/method_check/<UTC>/method_manifest.json` связывает обучение,
источники и каждый повтор. Результаты находятся в `verification/vNNN`:
`method_noise_centers.csv`, `method_pixel_status.csv`, `method_joint_status.csv`,
`method_summary.csv`, `method_bipolar_results.csv`, `method_bipolar_points.csv`,
`method_window_diagnostics.csv`, опционально `window_grid_points.csv`.
PNG/PDF показывают все окна рядом, полные двусторонние кривые по повторам,
карты среднего порога, остатка, повторяемости и полуширины интервала.

Остановленная серия имеет manifest `failed`/`interrupted`; завершенные raw
сохраняются. Офлайн-анализ неполной серии допустим с явными неполными статусами.
Автоматическое аппаратное resume всей серии пока не реализовано. Не надо
ставить RUN.resume=True: запустите новую независимую серию или обработайте
сохраненные измерения. На Windows используйте короткий RESULTS_DIR, например
C:/kpx_results: длина raw-временного пути проверяется до открытия приборов.

## Проверка реализации

Тесты используют аналитические кривые и заглушки границы существующего
характеризатора, не модель связи с настоящей ASIC. Проверены оба направления,
все коды/повторы полного скана, два независимых края, неполные/невалидные данные,
Student-квантили, заморозка всех трех карт, отказ при несовпадении LUT,
сохранение исходного знаменателя и manifest при ошибке. Реальная применимость
оператора счета и доверительной модели проверяется только на стенде.
