# Изменения 2.1.0 (архив v023)

- Новый method_verification: готовые либо однократно обученные trim-карты всех
  выбранных компараторов фиксируются, затем выполняются новые noise/S серии.
- GAIN фиксируется до noise-измерений; последовательные AB/BC/CD используют одну
  общую конфигурацию пикселей. Источники и хеши записываются в manifest.
- SCURVE.scan_coverage="full_bipolar": шаг 1 во всем заданном диапазоне, все
  повторы, оба измеренных края и центральный шум без достраивания симметрии.
- Отдельные bipolar CSV/PNG/PDF и межоконные контрасты H; реальные рабочие окна
  можно исследовать явной сеткой верхних порогов без fit одиночного компаратора.
- Условные интервалы повторных noise-центров с поправкой на M*K, отдельной
  систематической границей и тремя решениями о допуске. Без явных предпосылок
  результат остается неподтвержденным. Нет новой зависимости от SciPy.
- METHOD_TRIM_REFERENCE в .env; верхнеуровневый и офлайн-запуск через run_test.
  Подробный протокол и ограничения: comparator_characterization/METHOD_VERIFICATION.md.
- Аппаратное resume допускается только с текущей версией framework; старые
  результаты остаются доступны как офлайн-данные и источники trim-карт.

# Изменения 2.0.0

- Аппаратная проверка GAIN сохраняется в коротком независимом дереве
  `RESULTS_DIR/gain_check/vNNN/rNNN_WINDOW_gXX`, а связь с исходным анализом,
  FCLK и pattern остается в manifest. Это устраняет переполнение `MAX_PATH`
  при записи временных raw CSV на Windows.
- До открытия приборов рассчитывается консервативная длина самого глубокого
  raw-пути. Слишком длинный `RESULTS_DIR` отклоняется до первого `GET_SHOT` с
  инструкцией сократить путь.
- Исправлен повторный noise-fit для S-кривой с одним валидным повтором: пустой
  `sem_count` из CSV теперь считается неопределенным SEM, а не строкой. Fit
  продолжает работу с единичными весами и сохраняет диагностический признак.
- Числовые столбцы noise-fit нормализуются до разбиения на процессы. Невалидные
  точки порога или счета исключаются с явным счетчиком, сырые CSV не изменяются.

- Новая несовместимая пользовательская конфигурация v2. Основной файл сокращен
  до типизированных блоков тестов, пути перенесены в корневой .env, advanced
  алгоритмические/fit/GAIN веса и аппаратные детали в high_level/metadata.py.
- Один SCURVE_NOISE_REFERENCE для обычных S-кривых и GAIN-свипа, без скрытого
  приоритета. Clock trims, GAIN source, offline source и resume имеют разные роли.
- Единый запуск python -m comparator_characterization с RUN.test или --test;
  --check-config проверяет выбранный сценарий без подключения к приборам.
  Hardware gate по умолчанию False. Отдельные скрипты обновлены на v2.
- Resume включается явно RUN.resume, CSV GAIN-карта явно gain_source="csv".
  EO-grid применяется только выбранным тестом eo_sweep, не другими режимами.
- Удалены _UG/GAIN_MAP и плоские настройки, дубликат initialization clock,
  неработающие common-mode/early-stop/coarse stop параметры, paired_background
  mirror и миграция аппаратного resume старых версий. Низкоуровневый API стенда
  и чтение уже измеренных reference/raw результатов сохраняются.
- .env reader не исполняет подстановки, сохраняет Windows backslashes и UNC,
  проверяет неизвестные/повторные ключи. Нет новых зависимостей.
- Фактически использованная конфигурация и SHA256 .env записываются в результаты.
  Описаны отдельные сценарии и таблица нужных ссылок в high_level/README.md.
- Удалены дублирующие offline-входы plot_characterization.py и
  high_level/analyze_all_windows.py. Единый offline-анализ распознает ALL сам;
  применяет текущие metadata-настройки и перестраивает дочерние отчеты.

# Изменения 0.22.0

- `CHECK_EQ_GAIN_MAP=False` включает при True продолжение GAIN-анализа через
  реальное программирование индивидуальных PX_GAIN и повторные измерения.
  При False верхнеуровневый анализ остается полностью офлайн.
- Новая noise-база измеряется с уже примененной смешанной GAIN-картой, затем
  снимаются S-кривые. Сохраняются исходные comparator trims, точные REF-пары,
  Cinj и shutter exposure; прогноз не подменяет реальные результаты.
- Перед открытием приборов проверяются все задания: исходные SHA256,
  pixel selection, threshold LUT, REF-пары, trim, заряд, экспозиция и source
  CTRL/PWM settings. Неопределенные коды требуют явного разрешения.
- `CHECK_EQ_GAIN_MAP_ALL_WINDOWS=True` проверяет одну явно выбранную карту
  опорного окна во всех AB/BC/CD. `CHECK_EQ_GAIN_MAP_REFERENCE_WINDOW` должен
  быть задан пользователем; автоматического выбора/смешивания карт нет.
  Между окнами сохраняются одинаковые GAIN и все три source trim-карты.
- Добавлены CSV и графики до/прогноз/измерение, реальные карты усиления,
  амплитуды, баз, остатков и распределений. В ALL есть трехоконные карты
  и общие/дифференциальные диагностические признаки без утверждения причины.
- Результаты каждого аппаратного прохода, его raw и статус сохраняются
  отдельно. Исходные карты остаются предложениями; measured_gain_map.csv
  фиксирует факт измерения и пригодность отклика, не неуказанный допуск pass/fail.
- Автоматическая новая trim-эквализация не выполняется. Описан следующий
  финальный этап, для которого нужно выбрать межоконные цели.

# Изменения 0.21.0

- Добавлены карты эффективной базы, сигнальной амплитуды и усиления A/Q для
  каждого измеренного GAIN-кода и каждой ступеньки, а также зависимости отклика
  каждого пикселя от GAIN. Базовая линия и прежний пространственный анализ
  сохраняются. Цветовые диапазоны покодовых карт общие внутри одной ступеньки.
- При одной ступеньке усиление вычисляется напрямую:
  `G[мВ/кэ] = (V50 - baseline)[В] * 10^6 / Q[электроны]`.
  Многоточечный наклон сохраняется отдельно, если хватает данных.
- Новый офлайн-запуск `high_level/analyze_gain_sweep.py` принимает завершенный
  свип и `TARGET_GAIN`. Цель определяется по медиане (или среднему) матрицы при
  равномерном целевом коде. Отсутствующий целевой код в любом запрошенном окне,
  FCLK или режиме инжекции блокирует анализ до создания выходных файлов.
- Для каждого пикселя предлагается только реально измеренный код. Выбор не
  предполагает монотонность GAIN; при одинаковом результате сохраняется код,
  ближайший к целевому. Неопределенные пиксели получают явный статус.
- Сохраняются совместимые с `GAIN_MAP_CSV` карты, цели, покодовые метрики,
  прогнозы, сводки разброса и графики амплитуды, базы и усиления до/прогноз.
  Смешанная карта остается предложением до повторного аппаратного измерения.
- Общая noise-база явно отмечается как предполагаемая независимой от GAIN.
  Измеренная база при том же GAIN предпочтительна; центры при другом trim или
  известной другой FCLK не подставляются. Обновлен справочник метрик.

# Изменения 0.20.0

- Эквализация предварительно измеряет trim 0, 16 и 31. Точка 16 служит
  измеренным якорем, но не получает предпочтения при выборе кода. Алгоритм
  выбирает линейную или кусочно-линейную модель по разрешимости изгиба и
  минимизирует итоговый разброс эффективных порогов. Разворот у края
  фиксируется и получает расширенную локальную проверку.
- `_UG` принимает число либо список/tuple. Свип сохраняет каждое усиление в
  отдельном `gain_XX` и может использовать
  `UG_SWEEP_NOISE_REFERENCE_EXPERIMENT` без повторного noise scan.
- Добавлен `REFERENCE_MODE="manual"` с точными кодами REF1/REF2 и одним
  пользовательским эквивалентом ступени. Значение используется для расчета
  номинального заряда и не маскируется под измерение LUT.
- Анализ, сводки, пространственная компенсация и графики разделяют результаты
  разных `gain_sweep_code`.
