# Характеризация компараторов: руководство пользователя

Пакет `comparator_characterization` выполняет noise scan, эквализацию локальных
trim-кодов, измерение S-кривых, сравнение режимов групповой инжекции и полный
офлайн-анализ сохраненных данных. Полярность микросхемы скрипты не изменяют.

## С чего начинать

Для обычной работы нужны только файлы в каталоге
`comparator_characterization/high_level/`:

| Файл | Назначение |
|---|---|
| `characterization_config.py` | Все пользовательские пути и параметры |
| `preview_ref_selection.py` | Без стенда показать выбранные пары REF1/REF2 |
| `run_noise_equalization.py` | Noise scan и оптимизированная эквализация |
| `run_full_trim_sweep.py` | Полные noise-кривые для trim 0..31 |
| `run_scurve.py` | Отдельный S-curve тест с выбранным режимом инжекции |
| `run_full_characterization.py` | Noise, эквализация и S-кривые одним экспериментом |
| `run_crosstalk.py` | Сравнение `all`, `tile_2x2`, `tile_4x4`, `tile_8x8` |
| `plot_characterization.py` | Повторный анализ и построение графиков без стенда |

Остальные модули пакета `comparator_characterization/` редактировать для
типового запуска не требуется.

Первый запуск:

1. Откройте
   `comparator_characterization/high_level/characterization_config.py`.
2. Задайте `WINDOW`, пути к threshold LUT, REF LUT, Matrix JSON и GAIN CSV.
3. Задайте `INJECTION_STEPS_MV` и нужный `SCURVE_PATTERNS`.
4. Проверьте параметры УПО и генератора.
5. Выполните
   `python -m comparator_characterization.high_level.preview_ref_selection`
   и проверьте таблицу.
6. Только после этого установите `ENABLE_HARDWARE_RUN = True`.

## Окна и счетчики

| Окно | Верхний компаратор | Исследуемый компаратор | Пороговый ЦАП | Trim | Счетчик |
|---|---|---|---|---|---|
| AB | CMP_A | CMP_B | `DAC_CMP_B` | `PX_CMPB_TR` | High |
| BC | CMP_B | CMP_C | `DAC_CMP_C` | `PX_CMPC_TR` | Mid |
| CD | CMP_C | CMP_D | `DAC_CMP_D` | `PX_CMPD_TR` | Low |

Самостоятельная характеризация CMP_A пока не выполняется. Публичные координаты
в функциях и CSV всегда имеют порядок `(physical_column, physical_row)`. По
умолчанию исследуется принадлежащая проекту половина: Col 16..31, Row 0..31.

## Автоматический выбор REF1 и REF2

### Формат LUT

Для REF1 и REF2 передаются пути к полным измеренным передаточным
характеристикам. Каждый CSV должен содержать столбец кода и столбец измеренного
напряжения. Поддерживаются названия наподобие:

```text
code,voltage_V
DACCode,measured_value_mV
```

В `comparator_characterization/high_level/characterization_config.py`:

```python
REFERENCE_DAC_LUTS = {
    "REF1": "calibration/REF1.csv",
    "REF2": "calibration/REF2.csv",
}
REFERENCE_LUT_VOLTAGE_UNIT = "auto"  # либо V, mV, uV
INJECTION_STEPS_MV = (10.0, 20.0, 30.0, 40.0)
```

Режим `auto` определяет единицу по имени столбца. Если столбец называется просто
`Voltage`, значение считается заданным в вольтах. В неоднозначном CSV единицу
нужно указать явно, потому что скрипт намеренно не угадывает ее по диапазону
чисел.

### Правила выбора пары

Для каждой требуемой положительной ступеньки скрипт:

1. Использует только реально измеренные строки LUT, без экстраполяции.
2. Отбрасывает коды меньше `MINIMUM_REFERENCE_CODE`. Значение 401 означает
   строгое условие `REF1_code > 400` и `REF2_code > 400`.
3. При необходимости отдельно применяет нижний предел измеренного напряжения
   `MINIMUM_REFERENCE_VOLTAGE_V`.
4. Оставляет только пары с физическим условием `V_REF1 > V_REF2`.
5. Минимизирует ошибку `abs((V_REF1 - V_REF2) - requested_step)`.
6. При равной ошибке предпочитает заданный общий уровень, если указан
   `PREFERRED_REFERENCE_COMMON_MODE_V`, затем более высокие коды.
7. Выбирает разные физические пары для разных запрошенных ступенек.

До подключения к стенду выполните:

```bash
python -m comparator_characterization.high_level.preview_ref_selection
```

Будут показаны запрошенная и реально достижимая ступенька, ошибка, оба кода,
оба напряжения и общий уровень. Те же значения сохраняются в metadata и каждой
raw-строке S-curve измерения. Перед программированием еще раз проверяется
`V_REF1 > V_REF2`; нарушение останавливает запуск до записи кодов.

Вызов низкоуровневой функции выглядит так:

```python
result = characterize_comparator(
    client,
    threshold_calibration_files,
    reference_calibration_files={"REF1": "REF1.csv", "REF2": "REF2.csv"},
    injection_voltage_steps_v=(0.010, 0.020, 0.030),
    reference_calibration_voltage_unit="auto",
    # остальные параметры
)
```

Номинальный заряд рассчитывается как `Q = C_inj * (V_REF1 - V_REF2)`, где
`C_inj = 15 fF`, относительный допуск 20%. Поэтому заряд на графиках помечается
как nominal. Коды, измеренные напряжения и исходная ступенька всегда сохраняются
отдельно, чтобы расчет можно было повторить после уточнения емкости.

## Режимы инжекции S-кривой

Режим выбирается явно:

```python
SCURVE_PATTERNS = ("all",)
# или
SCURVE_PATTERNS = ("tile_2x2",)
```

Можно перечислить несколько режимов. `run_crosstalk.py` всегда запускает все
четыре режима для корректного сравнения плотности одновременно активных
пикселей.

Это выбор физического съема. При офлайн-анализе можно отдельно отфильтровать
графики уже измеренного режима, не удаляя остальные таблицы:

```bash
python -m comparator_characterization.high_level.plot_characterization results/EXPERIMENT --pattern tile_2x2
python -m comparator_characterization.high_level.plot_characterization results/EXPERIMENT --pattern all --pattern tile_8x8
```

Для полной принадлежащей половины 16x32:

| Режим | Фаз на одну пороговую точку | Активно пикселей в фазе | Время относительно `all` |
|---|---:|---:|---:|
| `all` | 1 | 512 | 1x |
| `tile_2x2` | 4 | 128 | 4x |
| `tile_4x4` | 16 | 32 | 16x |
| `tile_8x8` | 64 | 8 | 64x |

Да, в tiled-режиме анализируется не один выбранный пиксель подматрицы. Скрипт
последовательно перебирает все относительные позиции внутри tile. Например,
для `tile_2x2` выполняются фазы `(0,0)`, `(1,0)`, `(0,1)`, `(1,1)`. В каждой
фазе одновременно инжектируется одинаковая относительная позиция во всех
2x2 tile. После четырех фаз каждый физический пиксель полной половины был
активен ровно один раз. Для `tile_8x8` таких фаз 64.

При paired background на каждую фазу выполняются background-shot и signal-shot.
Грубая оценка числа `GET_SHOT` для одного режима:

```text
2 * amplitudes * threshold_points * repeats * phase_count
```

Поэтому рост времени в таблице является реальным. При неполном списке PIXELS
пустые группы пропускаются, а точный состав каждой фазы сохраняется.

Метрики наводок включают сдвиг V50 относительно самого разреженного режима,
отношение ширин S-кривой и фоново-скорректированную активность пикселей, которые
не должны были инжектироваться в данной фазе. Это индикаторы связи и наводок,
но не доказательство конкретного электрического механизма.

## GAIN и конфигурация пикселя

В активной фазе задаются:

| Поле | Активный пиксель | Остальные выбранные пиксели |
|---|---:|---:|
| `PX_TST_EN` | 1 | 0 |
| `PX_SH_EN` | 0 | 0 |
| `PX_BUF_NEN` | 1 | 1 |
| `PX_MASK` | 1 | 1 |
| `PX_SHT` | 2 | 2 |
| `PX_GAIN` | из карты | из карты |

Рекомендуемый GAIN CSV:

```text
column,row,gain
16,0,12
17,0,11
...
```

Также API принимает словарь `{(column, row): gain}`, двумерный список
`gain_map[row][owned_column_index]` или плоский row-major список
`gain_map[row * 16 + owned_column_index]`. `owned_column_index=0` соответствует
физическому Col 16. Все прочие биты исходного 32-битного слова сохраняются.

## Noise scan и эквализация

Стандартная экспозиция noise scan составляет 1000 us, повторов 10. Это
начальная рекомендация. Если счетчик около пика приближается к насыщению,
экспозицию нужно уменьшить и повторить эксперимент. Счетчик считается
останавливающимся на максимуме, а не переполняющимся по кругу.

`run_noise_equalization.py` не перебирает все 32 trim-кода для каждого пикселя.
Оптимизированный алгоритм выполняет:

1. Полные кривые при равномерных trim 0 и 31.
2. Выбор общей достижимой цели.
3. Интерполяционную оценку trim каждого пикселя.
4. Измерение локальных кандидатов около оценки.
5. Расширение локального диапазона для проблемных пикселей.
6. Финальную полную noise-проверку с индивидуальной trim-картой.

Это основной быстрый режим. Для научного изучения полной зависимости от trim
используйте `run_full_trim_sweep.py`. Он измеряет полные noise-кривые при каждом
равномерном коде 0..31, строит семейства кривых и распределений, а затем также
выполняет эквализацию. Такой запуск примерно в 16 раз длиннее только двух
endpoint scans, не считая локальной и финальной проверки.

## Генератор и S-кривые

Для Keysight 81150A/81160A задаются SQU 100 kHz, duty cycle 50%, уровни 0 и
3.3 V, `OUTP:LOAD 1 MOhm`, ручной источник trigger и аппаратный burst. Команда
`*TRG` программно имитирует trigger заранее вооруженного канала. Стандартное
число периодов равно 1000 и может быть изменено через `N_INJECTIONS` или
аргумент `n_injections` функции.

`GET_SHOT` запускается в отдельном потоке, потому что УПО блокирует этот вызов до
конца экспозиции. После `SHUTTER_START_DELAY_S` основной поток отправляет только
`*TRG`, ждет рассчитанную длительность burst и защитную паузу. Других команд УПО
до завершения `GET_SHOT` нет. Число периодов подтверждается SCPI queryback, но
это не независимый физический счетчик импульсов.

Перед первым реальным запуском осциллографом проверьте 0 V в покое, уровни
0..3.3 V, 1000 периодов после одного `*TRG` и один полезный отрицательный фронт
на период. Для S-кривой исходная рекомендация экспозиции УПО равна 1 s.

При совместном запуске после noise-части программа останавливается и просит
вручную изменить экспозицию УПО. При отдельном `run_scurve.py` используется
`NOISE_REFERENCE_EXPERIMENT`: его статистика фона и финальная trim-карта
копируются в новый эксперимент. Фон масштабируется по длительности shutter, но
на каждой пороговой точке все равно выполняется собственный paired background.

## Графики

Примеры из статей используются только как ориентир по физическим величинам.
Стиль не копируется. Набор объединяет классические проверки Medipix/Timepix и
более современные карты параметров, интервальные представления и контроль
качества fit.

### Noise и trim

Автоматически доступны:

- распределения порога для trim 0, trim 31 и equalized;
- общий рисунок из трех распределений и трех пространственных карт;
- карты абсолютного порога и отклонения от медианы до/после эквализации;
- heatmap выбранного trim-кода, остаточного offset и noise sigma;
- медианная noise-кривая матрицы с диапазоном 10-90% пикселей;
- подробные raw-кривые и fit для выбранных пикселей;
- распределение качества fit и таблицы диагностических флагов.

После полного trim-sweep дополнительно строятся:

- все распределения порогов trim 0..31 на одном графике;
- медиана, диапазон 10-90%, noise sigma и доля успешных fit против trim-кода;
- все колоколообразные noise-кривые для выбранного пикселя;
- матричные медианные noise-кривые для всех trim-кодов;
- зависимость центра и ширины каждого выбранного пикселя от trim;
- по запросу 32 отдельные heatmap порога.

### S-кривые

S-кривая является сигмоидой. Колоколообразную форму имеет noise scan или
производная S-кривой. Поэтому сохраняются оба представления:

- все амплитуды и fit на одном графике для каждого выбранного пикселя;
- медианные S-кривые матрицы с диапазоном 10-90% и их производные;
- V50 и sigma как heatmap и распределение для каждой амплитуды и режима;
- V50 и sigma матрицы против измеренной ступеньки или nominal charge;
- амплитудная зависимость V50 каждого выбранного пикселя;
- nominal gain map и распределение gain при трех и более амплитудах;
- точность подбора REF-пар: requested против actual и ошибка;
- fit quality и сводные метрики наводок для разных injection patterns;
- попиксельные карты и распределения delta V50 и изменения sigma относительно
  самого разреженного режима.

Конкретные пиксели задаются при повторном анализе:

```bash
python -m comparator_characterization.high_level.plot_characterization results/EXPERIMENT --pixel 16 0 --pixel 23 17
```

Если `--pixel` отсутствует, автоматически выбираются несколько пикселей по
квантилям распределения. Полные 32 trim heatmap включаются отдельно:

```bash
python -m comparator_characterization.high_level.plot_characterization results/EXPERIMENT --all-trim-heatmaps
```

Другие полезные параметры:

```bash
python -m comparator_characterization.high_level.plot_characterization results/EXPERIMENT --no-pdf --dpi 200
python -m comparator_characterization.high_level.plot_characterization results/EXPERIMENT --representative-pixels 10
python -m comparator_characterization.high_level.plot_characterization results/EXPERIMENT --pattern tile_4x4
```

Каждый повторный анализ создает новый `analysis/vNNN`, не перезаписывая старые
таблицы и рисунки.

## Сохраняемые данные и восстановление

Каждый завершенный shot атомарно сохраняется отдельным CSV до перехода к
следующей точке. В raw остаются 64-битное слово счетчика, части Low/Mid/High,
декодированное значение, saturation, координаты, DAC-коды и напряжения, trim,
GAIN, фаза инжекции, requested/programmed injection count, REF-пара и charge
metadata. Ошибки записываются отдельно.

Resume разрешен только при совпадении settings, LUT-хешей, Matrix JSON,
GAIN-карты, выбранных пикселей и счетчика. Изменение только способов анализа
делается офлайн и не требует повторного измерения.

## Методическая основа

Реализация не пытается буквально воспроизвести один рисунок. Она использует
подтвержденные для семейств Medipix/Timepix приемы:

- пороговые noise scans, endpoint/full trim scans и распределения baseline;
- CDF/probit fit S-кривых и карты V50/sigma;
- многоамплитудную электрическую инжекцию и fit отклика V50 от заряда;
- полнопиксельные карты параметров, распределения, интервалы и fit-quality.

Полезные первичные источники:

- Timepix4 front-end characterization: <https://doi.org/10.1088/1748-0221/17/07/P07006>
- Timepix3 time and energy calibration: <https://cds.cern.ch/record/2649493>
- Medipix3RX characterization: <https://doi.org/10.1109/TNS.2015.2425227>
- Medipix3RX equalization method: <https://doi.org/10.1016/j.nima.2015.08.029>
- Medipix4 characterization: <https://arxiv.org/abs/2310.10188>
- Timepix4 assembly timing characterization: <https://arxiv.org/abs/2404.15499>

Список ограничен работами, которые прямо поддерживают используемые физические
метрики. Графики проекта расширены диагностическими вариантами и не выдаются за
копии публикационных фигур.

## Аппаратные ограничения

- Python не задает и не читает длительность shutter в УПО.
- Python не видит физический сигнал открытия shutter, поэтому используется
  настраиваемая задержка.
- SCPI queryback не заменяет осциллографическую проверку числа фронтов.
- Пороговый и REF LUT должны быть измерены на конкретном стенде.
- Заряд остается nominal, пока 15 fF и его допуск не измерены точнее.
- CMP_A как самостоятельный канал пока вне области реализации.
