# Практическое сравнение калибровки CD

Запуск из корня распакованного проекта:

```shell
python run_calibration_comparison.py
```

Или вызов из собственного Python-сценария:

```python
from calibration_comparison import run_calibration_comparison

if __name__ == "__main__":
    result = run_calibration_comparison()
    print(result["report_path"])
    print(result["analysis_archive"])
```

Защита `if __name__ == "__main__"` нужна для параллельного анализа на Windows.
Сценарий не требует изменения прежнего `characterization_config.py`, создания
`.env` или подключения осциллографа/внешнего генератора. Используются уже имеющиеся
NumPy, pandas и matplotlib. Пакет с GUI остается совместимым с прежними запусками.

## Интерфейсы и органы управления

В актуальном проекте 65 логических EO-полей и 10 локальных PX-полей. Сценарий
использует существующие классы, без нового протокола связи:

| Интерфейс | Возможности и использование |
| --- | --- |
| `MGPDClient`, TCP к MGPDLab | READ_BYTE/WRITE_BYTE, FCLK, CTRL/PWM, загрузка PX, GET_SHOT и GET_PIXEL |
| `Configuration.set_data/get_data` + `EO_cfg` | Режимы ЗЧУ, дискриминаторов, буферов, REF и bandgap. Логические поля записываются с сохранением соседних битов |
| `DAC_CMP_BIAS_LSB` | Общий 10-битный код: младшие 8 бит в 0x8014, старшие 2 в битах 4..5 адреса 0x8015 |
| `DAC_CMP_BIAS_LSB_TR` | Общий 4-битный подстроечный код в битах 0..3 адреса 0x8015. Здесь фиксирован 3 |
| `PixelMatrixConfiguration`, `PIXEL_CODEC` | Отдельные 32-битные PX-слова, не TEST_CONF. GAIN, SHT, MASK, TST_EN, SH_EN, BUF_NEN, четыре 5-битных trim |
| `DAC_CMP_D`, `DAC_CMP_C` | Сканируемый нижний порог D и физически нелимитирующий верхний C, выбранный по LUT |
| `DAC_TST_REF1`, `DAC_TST_REF2`, CTRL | Два уровня тестовой ступени и их переключение. TEST_CONF настраивает отдельный тестовый пиксель, а не матрицу |
| `MGPDMeasurementBackend`, `UpoPwmShotExecutor` | Уже существующие последовательность экспозиции, декодирование LFSR, восстановление связи и FCLK |
| PyVISA / `Oscilloscope` / `TwoChannelGenerator` | Доступны в остальном проекте, но данному сценарию не нужны |

Запросы к одному УПО остаются последовательными. Параллельные процессы
обрабатывают только независимые кривые, с ограничением числа процессов и
размера очереди. Удвоение числа потоков чтения GET_PIXEL не ускоряет один
последовательный TCP-интерфейс и здесь не используется.

## Зафиксированные условия

- MGPDLab запущен, TCP `127.0.0.1:0xBEEB`, timeout 8 с.
- Shutter в УПО равен 10 мс. Это подтвержденное оператором значение, Python
  не умеет его прочитать или установить. В УПО `MODE_CNT=0` (16 бит),
  `MODE_READ=010`, `CRW_MODE=0`, оконный режим включен. Образ настроек УПО,
  загружаемый самим GET_SHOT, должен содержать эти же значения.
- Полярность и PUF сохраняются как в начальном OMR. Их изменение во время теста,
  в том числе при загрузке настроек УПО, блокирует дальнейший съем.
- Физическая матрица 32x32. Измеряются только Col=16..31, Row=0..31, то есть
  512 пикселей. Другая половина при инициализации записывается нулями, как в
  существующем характеризаторе. Измерения и статистика на нее не распространяются.
- Только окно CD, нижний компаратор CMP_D, счетчик `low`, поле `PX_CMPD_TR`.
  A/B/C не калибруются, корреляции окон и наводки не анализируются.
- GAIN=4, SHT=2, SH_EN=0, BUF_NEN=1. Локальные trim A/B/C остаются 16.
  Все прочие аналоговые режимы берутся из `EO_cfg.DEFAULT_REGISTERS`.
- Основной FCLK=100 МГц, FCLK экспозиции=5 МГц. Между пороговыми точками
  выдерживается установленная в текущем проекте задержка 0,1 с.
- CTRL PWM: 100 кГц, высокий уровень 5000 нс. Перед фоновым измерением CTRL=0.
- LSB: коды 500, 250, 750 при `DAC_CMP_BIAS_LSB_TR=3`. Сначала штатная точка
  500 для определения общих целей. Три уровня ограничивают продолжительность
  полного сканирования и проверяют режимы ниже/выше штатного. Измеренный ток
  в амперах этим кодам не приписывается.
- REF: ступени приблизительно 40 и 75 мВ, выбираются по приложенным LUT с одним
  общим REF1, оба кода в 401..900. Фактически выбранные коды и напряжения
  записываются в результаты. 40 мВ используется при подборе, 75 мВ как
  дополнительная, не участвующая в подборе, проверка.

Таблицы LUT используются без сглаживания и с сохранением их исходных хешей.
Немонотонность таблицы не заменяется предположением о знаке кода. Абсолютный
заряд, усиление в мВ/кэ и ENC не рассчитываются: точность REF при малых ступенях
и калибровка входной емкости для таких выводов не установлены.

Если существует `.env`, из него берутся только пути LUT, RESULTS_DIR и постоянной
маски BAD_PIXEL_MASK. Ссылки на старые noise/trim/GAIN-тесты не используются.
Проверка конфига и LUT без обращения к аппаратуре:

```shell
python run_calibration_comparison.py --check-config
```

## Последовательность эксперимента

1. Полная программная инициализация: EO defaults, readback, загрузка обеих
   половин матрицы, заданные GAIN/trim и LSB. Это не физический RESET кристалла.
2. При LSB=500 и trim=16 измеряются шум и обе REF-ступени. По медианам матрицы
   фиксируются общие цели b*, V50+*, V50-*. Они не меняются по данным проверки.
   Если для какой-либо цели нет ни одного валидного измерения, сценарий
   останавливается с сохранением данных вместо выбора фиктивной цели.
3. Для каждого LSB измеряются trim 0/16/31. Во всех этих исходных шумовых
   сканах выполняются ВСЕ коды 0..1023, шаг 1, два считывания на код, без
   пропуска пустых хвостов. Исходный скан LSB=500/trim=16 повторно не снимается.
4. Сигнальные сканы покрывают весь LUT грубым шагом 16. Для каждого пикселя
   обе переходные области уточняются с шагом 1. При отсутствии скобки
   выполняется дополнительный проход шагом 4. Ненайденный край остается
   неразрешенным. На каждом измеренном пороге сохраняются два сигнальных
   считывания и два соответствующих фоновых, без вычитания фона как
   тождественного шумового процесса при включенной инжекции.
5. P1 выбирает код по наибольшей ошибке b и V50+. P2 добавляет V50-.
   Все ошибки сравниваются в вольтах с одинаковым весом. При ранжировании
   добавляется описательный запас: максимальная доступная fit-оценка ошибки
   плюс разброс повторных оценок данного кода. Это не доверительная граница
   и не замена систематической погрешности LUT. Полнота этих оценок записывается
   в `guard_complete`; отсутствие оценки не маскируется признаком надежности.
   Предсказание кода
   использует отдельные кусочно-линейные измеренные зависимости каждой
   характеристики, а не обязательный одинаковый сдвиг трех уровней.
6. Предсказанные карты P1/P2 и соседние коды +/-1 измеряются. Для уже
   измеренного кода данного пикселя данные обучения переиспользуются.
   Итоговый код выбирается из реально измеренных, а не из одной интерполяции.
   P0 (только шум) также рассчитывается офлайн, но не проходит отдельную
   аппаратную проверку и не подменяет P1.
7. При наблюдаемой немонотонности до 16 наиболее выраженных проблемных
   пикселей на LSB проходят полный перебор оставшихся trim-кодов. Это
   ограничение времени. Для остальных сохраняется признак ограниченного
   поиска; глобальная оптимальность по всем 32 кодам не утверждается.
8. Карты фиксируются. Для КАЖДОГО LSB выполняются три новые проверки P1 и три
   P2. Перед КАЖДОЙ проверкой повторно загружаются исходные EO/PX, LSB и
   соответствующая замороженная карта. Порядок P1/P2 чередуется.
   Уровни LSB также циклически переставляются между повторами, чтобы каждый
   занимал разные позиции по времени. Это уменьшает смешение эффекта LSB
   с медленным дрейфом, но не доказывает отсутствие дрейфа.
   В каждом случае снимаются новый шум и две REF-ступени. Шум между разными картами не переиспользуется.
   Для двух амплитуд одной неизменной карты один шумовой профиль общий.
9. Обработка и сохранение отчета. Откроется локальная HTML-страница с графиками.

В локальном поиске и проверке шум снимается грубым поиском и индивидуальными
плотными областями. Если шумовой отклик пикселя не найден, поиск расширяется
до полного прохода. Полный исходный диапазон на каждом LSB и trim 0/16/31
не сокращается этим механизмом.

Число 1000 не используется как точно измеренное число событий. В каждом shot
хранятся номинал F_PWM*T_shutter, его происхождение и отсутствие аппаратного
счетчика фронтов. Fit S-кривой имеет свободное плато. В таблицах отдельно
приводятся уровни плато и их отношение к номиналу. Они не объявляются точным
числом инжекций, в частности при неполной эффективности регистрации.
Две полярности не нормируются на 2*1000 автоматически.

## Контроль сопоставимости

Обучающие данные общие для P1 и P2: это сравнение использования разного объема
информации на одинаковых входных данных. На их сбор не тратится двойное время.
Стоимость обучения нельзя выдавать за время двух независимо обученных
алгоритмов. Реальное число GET_SHOT, чтений пикселей и затраченное время
сохраняются по стадиям, методам и LSB.

Методика не меняет GAIN по пикселям. Различия ЗЧУ проявятся в полуразмахе,
амплитудах относительно шумового центра, асимметрии и остатках. Нельзя
приписывать эти различия одному ЗЧУ только по цифровому счету. Устойчивость
дополнительной REF-ступени оценивается отдельно от основной.

Раздельная регистрация фронта/спада и физический смысл счетного оператора
текущим TCP API не подтверждаются автоматически. Поэтому в результатах
остается `counter_operator_validated=false`. Скрипт измеряет два края
цифрового отклика, не утверждая, что выполнил независимое временное стробирование
каждой полярности. Центральная шумовая область сохраняется на графиках и
исключается из fit по измеренному фону (не более 0,01 номинала).

## Чекпоинты и возобновление

`raw.sqlite` содержит отдельные таблицы scan / shot / pixel sample. Каждое
завершенное GET_SHOT со считыванием нужных пикселей фиксируется одной транзакцией
с полной синхронизацией. Сохраненные raw-строки не перезаписываются.
Точки, повторы и завершенные сканы восстанавливаются по этой базе, а не только
по крупному состоянию "шум завершен".

Остановить можно Ctrl+C. Данные и статус сохраняются, CTRL и инжекция
отключаются при достоверном состоянии связи. При неизвестном состоянии УПО
безопасное восстановление аппаратуры не имитируется.

Повторный обычный запуск автоматически продолжит последний незавершенный
эксперимент. Также доступны явные команды:

```shell
python run_calibration_comparison.py --resume results/calibration_comparison/<каталог>
python run_calibration_comparison.py --new
```

`--new` создает отдельный эксперимент, не удаляя предыдущий. При возобновлении
сначала заново загружаются EO/PX, LSB и карта текущего этапа. Затем пропускаются
сохраненные коды и повторы. Возможна потеря только текущего незавершенного
считывания, находившегося в памяти, а не уже завершенного шумового скана.
Сохраненный фон, для которого сигнал еще не снят, не используется как новая
пара после перезапуска. Записывается новая пара; старый фон остается в raw.
Если измерения уже завершены, а построение отчета оборвалось, повторный вызов
восстановит только отчет без подключения к аппаратуре.
Прерванные сканы экспортируются с `scan_complete=false` для диагностики,
но не включаются в итоговое сравнение как завершенные проверочные серии.

Изменение кода, настроек, маски или LUT блокирует аппаратное продолжение с
другим контрактом. В таком случае можно заново анализировать исходные данные
либо запустить отдельный эксперимент. Возобновление не отменяет возможный
дрейф температуры/аппаратуры; времена и границы сеансов сохранены для анализа.

## Результаты

Все находится в `results/calibration_comparison/<UTC_идентификатор>/`:

| Путь | Назначение |
| --- | --- |
| `raw.sqlite` | Полные неизменяемые счетные данные и метаданные каждого shot |
| `inputs/` | Копии использованных LUT |
| `run.json`, `events.jsonl` | Состояние этапов, параметры, восстановление и ошибки |
| `analysis/scans/` | Fit и агрегированные точки каждого скана для Python |
| `analysis/trim_maps.csv` | Карты P0/P1/P2 для каждого LSB |
| `analysis/targets.csv` | Зафиксированные цели |
| `report/index.html` | Отчет для оператора, PNG/PDF лежат рядом |
| `analysis_for_chat.zip` | Компактный набор для передачи в чат, без raw.sqlite |

В компактном архиве: все пиксельные характеристики/статусы, карты, диагностика
trim, размах/шаг коррекции, зависимость доли в допуске от LSB и допуска,
матрицы решений, счетная нормировка, время, выбранные кривые, контракт и LUT.
Ограничение архива 20 МиБ. Если выбранные кривые превышают бюджет, они
исключаются из архива, а все основные пиксельные метрики сохраняются.
Графики и сырые данные в этот архив не входят. Локальные raw могут быть большими.
Графики выбранных S-кривых увеличивают область обоих краев вместе с шумовым
центром. Полный измеренный диапазон, включая нулевые хвосты, остается в таблицах.
Для P1/P2 используются согласованные шкалы карт и графиков ошибок.

Сводка не выдает сертификат годности: допустимая ошибка и систематическая
неопределенность микросхемы не заданы. Вместо произвольного фиксированного
порога строится зависимость результата от допуска анализа 0,25..32 мВ.
Все 512 пикселей остаются в знаменателе, маскированные/непрочитанные не
объявляются годными. Fit-ковариация и разброс повторов сохраняются как
описательные оценки, без обещания одновременного доверительного покрытия.

`same_map_diagnostic_counts.csv` показывает расширение проверки одной карты.
`independent_confusion.csv` сравнивает решение по первому новому скану с
отдельной опорной оценкой по следующим двум. Неизвестные результаты
учитываются отдельным столбцом. Это расхождения независимых измерений,
не установленный диагноз неисправности пикселя.

Повторный анализ без аппаратуры:

```shell
python run_calibration_comparison.py --analyze results/calibration_comparison/<каталог>
python run_calibration_comparison.py --analyze results/calibration_comparison/<каталог> --rebuild
```

Первый вариант использует сохраненные fit-таблицы. `--rebuild` пересчитывает
их из raw.sqlite, не подключаясь к УПО. Старый текст статьи не изменяется.
